## Failure and repair

`ViewportPaintGraph` rejected a line or rectangle when its geometry bounds missed
the viewport clip. A thick stroke, square cap, or rectangle miter can still reach
inside that clip. The result was missing visible pixels at the viewport edge.

The existing culling atom now includes a conservative stroke envelope for LINE
and DRAW_RECT. It reads line width once per replay and uses long intermediate
bounds, including clip right/bottom, to avoid overflowing the envelope arithmetic.
Fill and text handling, the integral-translation fast path, detached-template
reuse, affine replay and caller-transform restoration are preserved.

The clip argument remains the existing coarse culling hint; the real GC owns
exact clipping. Tests set the same clip on both GCs before comparing all pixels.
No public API, JNI, widget/item identity, event-routing or accessibility changes.

## Executed evidence

Java 21.0.12, Linux GTK3/X11 under Xvfb, existing SWT `4975r7` native libraries:

| Check | Result |
| --- | --- |
| Baseline graph + expanded graphics tests | 5 pass, 4 fail with missing native pixels |
| Repaired graph + same tests | 9 pass, 0 skipped |
| Recipe replay/fixed point, source drift refusal, missing-source refusal | 3 pass, 0 skipped; OpenRewrite 8.17.1, Maven 3.9.11, offline cached dependencies |
| Java compilation, complete selected GTK source roots | 484 sources, pass |
| Java compilation, complete selected Win32 source roots | 663 sources, pass |
| Java compilation, complete selected Cocoa source roots | 624 sources, pass |

The four added methods in `Test_org_eclipse_swt_internal_ViewportPaintGraph` cover
thick lines, square caps, rectangle joins, and fractional widths. Existing tests
continue checking template reuse, off-screen culling, affine restoration and cycles.

These are Java compilation and focused native GTK results. Cocoa/Win32 native
execution, GTK4, full Tycho/reactor, API tooling and whole-widget stress acceptance
remain outstanding. Existing native libraries were reused; no native binaries are
added to the PR.

The integrated Maven command was attempted. Tycho stopped before the test phase:
the SWT bundle requires GTK fragment version `3.136.0`, while the selected fragment
still advertises `3.135.100`. That dependency-resolution failure is not a passing
reactor result and is separate from this Java-only culling repair.

Run the existing integrated SWT test entry point on a configured platform:

```sh
mvn verify -pl :org.eclipse.swt.tests -am -DskipNativeTests=false \
  -Dsurefire.failIfNoSpecifiedTests=false \
  -Dtest=Test_org_eclipse_swt_internal_ViewportPaintGraph
```

## Recipe and concurrent work

The two Java postimages are generated by the existing Synexia
`M3HashPinnedJavaSnapshotRecipe` through crate `swt-viewport-stroke-culling-v1`.
Its exact pre/post SHA-256 manifest, retained EPL-2.0 snapshots and replay/refusal
tests live in `hsoliwal/com.synexia`, under `synexia-openrewrite-recipes`.

This repair complements draft SWT #32 (paint/input state) and #34 (scrollbar
visual scenes). Those branches were inspected rather than recreated. Forward
integration must preserve their additions; the exact-source recipe deliberately
refuses a changed source revision until its candidate has been reconciled.
