SWT M3 fragment packaging notice (bundle org.eclipse.swt.m3, leaf 18, 2026-10-31)

The fragment org.eclipse.swt.m3 of org.eclipse.swt holds the SWT source trees "Eclipse SWT Render M3" and
"Eclipse SWT GPU M3" (EPL-2.0, or Apache-2.0 OR EPL-2.0, as the header of each file says; code adapted from the
SWT Initiative 31 donors keeps its EPL-2.0 notices) and embeds these jars unchanged, byte for byte, under lib/:

  lib/skija-shared.jar       io.github.humbleui:skija-shared:0.116.3       SHA-256 2e065693324dc5a8019518a2ef20db07f805281c5961e185d071c86ab8b3b9c1
  lib/skija-windows-x64.jar  io.github.humbleui:skija-windows-x64:0.116.3  SHA-256 5553be2214cbdc7d1358d966dba90443a31c54411f61c64a0720d3b0247ecc3a
  lib/types.jar              io.github.humbleui:types:0.1.1                SHA-256 549038f09cc1928f35bc0b583dc9865aff8450c5e8e0146328fe2ba48710ad35

The Skija version is set once (skija.version in bundles/org.eclipse.swt.m3/pom.xml); the types version is the one
that skija-shared 0.116.3 declares in its own POM. The build writes the coordinates and SHA-256 of every embedded jar
to META-INF/m3/SKIJA.tsv inside the fragment jar; a version change updates this notice with it.

Runtime selection is opt-in and off by default; SWT runs without the fragment, and every mode then falls back to the
stock path:
  -Dswt.widget.mode=m3|gpu   drawn widgets and M3 canvases through the M3 renderer (CPU raster or OpenGL)
  -Dswt.gpu=m3               retained GPU planes through the M3 backend (RetainedPlanes accepts gdi, retained, m3)
